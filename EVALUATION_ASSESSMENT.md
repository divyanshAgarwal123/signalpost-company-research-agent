# Signalpost scoring readiness

Checked 15 September 2026 against Builderr's [current challenge](https://builderr.ai/challenges/signalpost) and [scoring version 2 contract](https://builderr.ai/docs/signalpost-evaluation-harness.md). This is a local readiness assessment, not a Builderr score prediction. Builderr's field weights, checked reference union, independent entity labels and actual daily batches are unavailable.

**Version 1 is operationally prepared for submission, but prize qualification is unknown and external coverage is a high-risk hard gate.** Its public 1,000-profile artifact and matching manifest now exist; 12,690 material claims, claim-linked summaries and bounded evidence descriptors pass local structural checks. Independently measured 95% exact-entity precision, full raw-body hash verification, Builderr's external-company recall, full v2 refresh score and gallery UX remain unproven. A local operational pass does not override those hard gates.

The artifact selection includes **all ten development companies and all 100 organisations in the earlier validation slice**. Its site rate is an artifact-scale observation, not an independent holdout or estimate of the hidden daily test. A new `agent/data/holdout100.jsonl` contains 100 eligible organisations with zero overlap with that artifact. Its live run passed 100/100 terminal envelopes in 153 seconds with 647 reported requests; current-code replay of its saved sources has five cautious site claims and 1,293 material claims. The replay is a safety regression check, not a fresh live evaluation.

The current [readiness checker](agent/scripts/evaluate_v2_readiness.py) outputs `score_estimate: null` and `qualification_readiness: false`. The official starter's older `score_competition_v3.py` uses different point weights and cannot be used as a Builderr score. The reviewed-entry board shows provisional 65+ scores that still fail qualification for coverage or a wrong-company website, so Builderr's diagnostic feedback should drive the next exact-code revision.

An independent positive control on **MERCHANT GROUP AS (931966022)**, an organisation in Builderr's eligible universe, showed the external layers functioning **in one current run**: one terminal envelope in 120 seconds and 54 reported requests included an exact website, its description, one dated company article and the active NAV internship advert. The [Merchant legal page](https://merchant.no/selskap/vilkar) tied the site to the full legal name and registered place; the [13 September article](https://merchant.no/innhold/nyheter/merchant-vokser-storre-kunder-nye-ansatte) supplied dated activity. The [NAV public posting](https://arbeidsplassen.nav.no/stillinger/stilling/066dd2e6-7695-43fd-bd84-6e4482c72e32) names workplace **932019256**, and [Brønnøysund's subunit page](https://virksomhet.brreg.no/nb/oppslag/underenheter/932019256) establishes its parent relationship to Merchant Group AS. The website claim now carries a separate legal-page proof URL, hash and supporting text rather than relying on its branded homepage title alone. This control demonstrates a positive path; it is not a random-batch recall or score estimate. The rotating public NAV token was used only for this local experiment.

The next measurable gain must come from permitted external sources that expose an exact employer organisation number or an independently proved company site. NAV's [current feed](https://navikt.github.io/pam-stilling-feed/) provides the employer number and update/withdrawal events, but it cannot filter by company and its rotating public token is meant for experiments; a frozen entrant needs a registered consumer token. NAV states an advert cannot remain active for more than six months. Scanning all of that history in every 100-company run is expensive and a 400-page cap failed locally; the operational default returns exact matches from a **completed 90-day update window**, clearly marks older jobs unverified, and needs a lawful six-month job index plus incremental updates for strong recall. Brave's [licensed Search API](https://brave.com/search/api/) can discover candidate sites for about $0.005/query, but a key is not configured locally. Search output cannot be published as a claim. The runner's optional discovery path verifies any proposed site through fetched-page identity before promotion.

Before estimating a score, label exact company/site/job matches on unseen organisations; obtain a checked external-positive pool by family; measure recall and wrong-company publications; verify raw source spans and live refresh; run repeated 100-company batches under a true network request counter; then produce 1,000 completed profiles. Only Builderr can report the final points or award probability against its shared reference union.
